# Agent trace schema 1.3

Extends [1.2](v1.2.md) without changing raw-output, redaction, inference, or outcome meanings.

## Runtime observations

`rounds[].runtime_usage`, when available, contains provider-reported `prompt_tokens`, `completion_tokens`, `cached_prompt_tokens`, and numeric `runtime_fields`. Local prefill/generation durations use explicitly named nanosecond fields. Groq timing fields retain the provider's seconds units. Missing cached-token counts are `null` (unknown), never inferred from latency or prompt similarity.

`rounds[].prefix` contains application `system_sha256` and `tools_sha256` hashes. These compare application inputs, not the runtime's rendered templates or cache keys. Matching hashes alone do not demonstrate cache reuse; schema changes, protocol negotiation, and compaction can invalidate a prefix.

## Tool views and discovery

`tool_calls[].model_view` contains `result_ref` and `shortened`. When shortened, `output` is the inference-only view. The existing tool `output` remains the raw observed result, subject to trace limits. References are request-local and not persistent artifact IDs.

An omitted-but-enabled attempted call can have `execution_status: "deferred"`: its schema was made available, but its arguments were not executed. This is neither tool execution success nor a content-quality judgment. Disabled or notebook-forbidden tools cannot be promoted.

Dynamic tool schemas, resource inventories, and argument-repair guidance are captured in application context messages rather than appended to the stable core system prompt. System prompt references remain content-addressed as before.
