# Agent trace schema 1.0

Each JSONL record represents one main-agent execution. This reference describes the initial format; see the [changelog](CHANGELOG.md) for later versions.

## Execution record

| Field | Meaning |
| --- | --- |
| `schema_version` | `"1.0"`. |
| `trace_id` | Unique execution UUID. |
| `timestamp` | UTC execution start time in ISO 8601 format. |
| `conversation_id` | Conversation identifier when available. |
| `capture_policy` | Redaction policy version, text/result character limits, and binary omission policy. The redaction version is independent of the schema version. |
| `model` | Requested and resolved model identifiers, plus hardware profile. |
| `inference` | Supplied `think`, `temperature`, and `max_output_tokens`; omitted values can be `null`. Provider/native-tool metadata may also be present. |
| `max_rounds` | Permitted agent round budget. |
| `request` | Original `user_message`, supplied `messages`, `image_count`, and `interaction_mode`. |
| `preparation_tools` | Tool observations before the first model round, such as automatic vision preparation. |
| `rounds` | Ordered model rounds; see below. |
| `outcome` | Termination status, response, counts, and total duration. |

## Round record

| Field | Meaning |
| --- | --- |
| `round`, `timestamp`, `model` | Round number, UTC start time, and model identifier. |
| `input_messages` | Actual model input after context preparation/compaction; system messages use prompt references. |
| `context_messages` | Dynamic context supplied for this round, including retrieved context where available. |
| `exposed_tool_schemas` | Native tool schemas exposed to the model, or `null` for text-based tool instructions. |
| `available_tools`, `selected_tools` | Exposed tool names and tool names selected by the application. Text-based instructions remain in the captured prompt. |
| `inference` | Supplied inference settings and provider/native-tool metadata. `null` does not establish an effective provider default. |
| `provider_settings` | Observed provider payload settings, excluding messages/tools and credentials. |
| `model_response` | Streamed `content`, `thinking`, normalized `native_tool_calls`, and optional `finish_reason`/`truncated` marker. Not a byte-for-byte HTTP transcript. |
| `malformed_provider_frames` | Optional rejected provider frames, retained for diagnostics. |
| `parsed_tool_calls` | Calls accepted by the existing parser, including any argument substitutions it made. |
| `parse_diagnostics` | Parsing results such as `parsed`, `invalid_shape`, or `invalid_json`, with safe raw arguments/candidates and errors where applicable. |
| `tool_calls` | Observed tool attempts and results. |
| `decision`, `duration_ms` | Continuation/termination decision and monotonic elapsed duration. |

## Tool record

Tool records contain `name`, `arguments`, UTC `timestamp`, `execution_status`, and `validation`. Finalized attempts additionally contain `duration_ms`, `output`, and `error`. `effective_arguments`, when present, reflect application-injected execution arguments; private underscore-prefixed arguments are excluded.

Execution statuses include `pending`, `completed`, `failed`, `unavailable`, `skipped`, `cancelled`, and `interrupted`. Validation statuses are `not_observed`, `tool_returned_success`, or `reported_validation_error`. Validation remains owned by the tool: the logger does not perform independent schema validation or establish semantic correctness.

## Outcome record

- `status` and `termination_reason`: `completed`, `max_rounds_reached`, `cancelled`, `failed`, or `shutdown`. `running` is the in-memory initial state.
- `total_rounds`, `total_tool_calls`, `unparsed_tool_attempts`, `successful_tool_calls`, `failed_tool_calls`, `interrupted_tool_calls`, and `skipped_tool_calls`: operational counts. Tool totals include preparation tools and rejected text JSON candidates; not every attempt executed.
- `duration_ms`: total monotonic elapsed duration.
- `final_assistant_response` and `final_response_source`: captured final content and whether it came from the `model` or `application`; source can be `null` when no response exists.
- `quality_evaluated`: `false`. Completion and successful tool execution do not establish answer correctness.

## Prompt references and safe values

System messages use `{ "role": "system", "prompt_ref": "prompts/<hash>.json", "sha256": "<hash>" }`. The referenced JSON contains `schema_version` and captured `content`. The hash is calculated from the serialized sanitized content, not the original prompt text. Preserve prompt files alongside JSONL records.

Captured values are JSON-compatible and sanitized. A text value may become `{ "text": "…", "truncated": true, "original_chars": 123 }`; bounded structured results may use `preview_json` instead. Binary assets, cycles, unsupported types, non-finite numbers, and excessive nesting use `omitted` annotations. Known secrets become `[REDACTED]`. Consumers must not assume every content/output field remains a string or that exact original inputs are recoverable.
