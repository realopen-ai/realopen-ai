# Agent trace schema 1.2

This version extends [schema 1.1](v1.1.md) with agent identity, parent linkage, and coder-internal observations. Existing request, inference, safe-value, and outcome semantics are unchanged.

## Execution identity and storage

| Field | Meaning |
| --- | --- |
| `agent` | `general` or `coder`. Records predating this field represent the general agent. |
| `parent_trace_id` | Parent execution UUID for a delegated coder run; otherwise `null`. |
| `parent_tool_call_id` | Parent delegation's tool-call identifier when supplied; otherwise `null`. |
| `coder_task_id` | Coder task UUID, when task creation succeeds. |
| `sandbox_id` | Workspace identifier when available. |

General records remain at the configured trace root. Coder records use `coder/YYYY-MM-DD.jsonl`; their system prompts use `coder/prompts/<hash>.json`. Prompt references resolve relative to the directory containing their JSONL file. Standalone coder runs can have no parent. Each delegation has its own round budget, resolved model, duration, and termination status.

## Coder rounds and model attempts

A round represents one iteration of the coder loop. `model_response` and `parsed_tool_calls` describe the response consumed by that loop. `model_attempts` preserves the underlying calls, including recovery before transformation:

| Field | Meaning |
| --- | --- |
| `timestamp`, `duration_ms` | Attempt start time and monotonic elapsed duration. |
| `input_messages` | Actual captured input, with system-prompt references. |
| `exposed_tool_schemas` | Native schemas, or `null` for the JSON recovery call; text instructions remain in its messages. |
| `recovery` | Whether this is the JSON recovery attempt. |
| `response` | Sanitized provider-adapter response before recovery parsing, or `null` on request failure. |
| `error` | Error type/message and available HTTP status/body, or `null`. Credentials and sensitive values remain subject to redaction. |
| `inference`, `provider_settings`, `model_defaults` | Captured settings for this attempt, where observed. |

Recovery parse failures add an `invalid_recovery_response` parsing diagnostic. Invalid native argument strings remain in raw calls and diagnostics even if the existing coder parser replaces them with empty arguments. Tool `arguments` preserve the attempted input; `effective_arguments` reflect subsequent workspace-path normalization.

Tool records additionally expose `origin`: `model` for model-selected calls, `application` for application-triggered calls such as automatic preview startup. Refused rewrites and calls skipped after safety termination are recorded as `skipped`, not executed successes.

`tool_call_id`, when assigned, identifies the application's tool event. Match a child's `parent_tool_call_id` against the parent record's tool IDs to locate its delegation. Attempts skipped before event creation may have no ID.

The general trace records delegation arguments/results, not the child's internal tools. Analyze each agent's outcome independently: a completed parent does not imply its coder succeeded or produced correct code.
